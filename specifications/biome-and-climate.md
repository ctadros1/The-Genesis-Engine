# Biome And Climate Specification

Status: design specification, not implemented. Phase 6. Policy versions
`lifesim-biome-v1`, `lifesim-climate-v1`.

## Problem

`docs/05-world-model.md` has specified biomes, moisture, temperature, and
drainage since Phase 1 and none of them is implemented. `lifesim-worldgen-v1`
produces elevation, a land mask, and a food-capacity field; that is all.

Two consequences for the new goal. Biome-matched founder seeding
(`specifications/world-origin-modes.md`) has nothing to match against. And
the temperature field that Phase 13 thermoregulation needs, and that the
thermal-preference gene inherited-but-inert since Phase 2 was written for,
does not exist.

## Fields

Added to `lifesim-worldgen-v1`'s successor, `lifesim-worldgen-v2`. The
baseline generator remains a pure function of `(seed, config)`, so the
format 2 baseline-plus-delta save contract is unaffected.

| Field | Static or dynamic | Source |
|---|---|---|
| Elevation | Static | Existing |
| Land mask | Static, derived | Existing |
| Latitude proxy | Static | Y coordinate normalized |
| Base temperature | Static | `base - lapse * elevation + latitude term` |
| Moisture | Dynamic | Rainfall, evaporation, drainage, sea proximity |
| Temperature | Dynamic | Base plus season plus drift plus bounded weather |
| Biome | Dynamic, derived | Classified from elevation, temperature, moisture |
| Food capacity | Dynamic | Biome-dependent, replacing the current elevation-only field |
| Material yield | Dynamic | Biome-dependent (Phase 12) |

Moisture uses the deliberately simplified model `docs/04` already describes.
The project labels this ecological simulation, not weather forecasting, and
that label stands.

## Biome Classification

A bounded versioned registry, classified by threshold rules over
`(elevation, temperature, moisture)`. The starting set is the seven
`docs/05` already names: coast, grassland, forest, wetland, arid, highland,
water.

Classification is a **pure deterministic function evaluated in ascending
cell index**, with thresholds in versioned config and ties broken by
ascending biome ID. Biome is derived state: recomputed on load, never
stored, never trusted from a save.

A biome supplies constraints and resource behavior. It never supplies a
scripted organism role, and no rule anywhere reads a biome ID to grant or
deny a capability. Organisms experience temperature, moisture, and food
capacity; the biome label is a classification over those fields for human
and analysis legibility.

## Climate Drift

The mechanism behind the user-facing intuition of an ice age, and it is
deliberately not an era.

    temperature(cell, tick) = base(cell)
                            + season_amplitude * season(tick)
                            + drift_amplitude  * drift(tick)
                            + bounded_weather(cell, tick)

`drift(tick)` is a deterministic quasi-periodic function: a fixed sum of
sinusoids at incommensurate configured periods, all far longer than the
seasonal period. It is evaluated in fixed point from tick alone, with no
state and no accumulation, so it cannot drift numerically and needs no
storage.

The `ClimateDrift` stream (21) exists for an optional bounded stochastic
component and is unused under the default deterministic policy.

Consequences that matter:

- Cold and arid regions expand and contract over long timescales, so biome
  classification changes during a run and organisms must adapt, migrate, or
  die.
- **No code reads "the world is in an ice age."** There is no age state, no
  age transition, no era field, and nothing spawned or swapped because of
  one. `drift(tick)` is a temperature term, nothing more.
- An observer may look at the event log afterwards and call a sustained cold
  stretch an ice age. That is Phase 17's segmentation over recorded history,
  a label applied to the past, never a state the simulation entered. See
  `docs/25-emergence-and-epistemic-position.md`.

The distinction is not pedantic. If a rule could read the age, the age would
be causing outcomes, and every result about adaptation to climate would be a
result about our schedule instead.

## Determinism

- Classification and every field update iterate in ascending cell index.
- `drift(tick)` is stateless and derived from tick alone.
- All fields are fixed point; the diffusion-like moisture update conserves
  its totals exactly by construction.
- Biome is derived and excluded from the save, like phenotypes and bodies.
- Dynamic temperature and moisture **are** stored, since they carry history:
  checksum section `lifesim-climate-state-v1`, present only when the climate
  section is enabled.
- `lifesim-worldgen-v2` is a new generator version. Worlds generated by v1
  keep using v1: the generator version is inside the config hash, so a v1
  world's terrain checksum and fixtures are unaffected forever.

## Test Requirements

- Classification is a pure function; recomputation after restore is
  identical.
- Threshold boundary cases classify deterministically, with ties resolved by
  ascending biome ID.
- `drift(tick)` is exactly reproducible from tick alone at arbitrary tick
  offsets, including after a save and restore at an arbitrary point.
- Moisture conserves totals exactly over a long run.
- Temperature and moisture stay within configured bounds for every cell over
  a 10^6-tick run including full drift cycles.
- Biome distribution over a generated world is validated: no biome may be
  empty or occupy the entire map, or generation fails closed with an
  actionable error, as land-fraction validation already does.
- A v1-generated world reproduces its existing terrain checksum and the
  Phase 1 and Phase 2 fixtures exactly.
- Climate section disabled reproduces the Phase 5 fixture exactly.
